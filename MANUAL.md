# MANUAL — Мануал по функциям MCP Socket

> Русская версия. Каждая функция: что делает, когда использовать, параметры,
> пример. Список тулов соответствует версии 2.6.0 (18 MCP-тулов).

---

## Как это устроено

```
MCP-клиент (ZCode / Claude / любой) → stdio → mcp_server/server.py → TCP :9876 → аддон в Blender
```

Аддон живёт в Blender, сервер — тонкий посредник. Два способа пользоваться:

1. **Через агента** — агент зовёт тула (их 18) или пишет код через `execute_code`.
2. **Руками в панели** — N-панель вьюпорта, вкладка **MCP Socket**.

---

## 1. Тулов агента (18)

### База: что за сцена

#### `ping`
Проверка связи. Возвращает визитку: версия моста/Blender, pid, порт, имя сцены,
файл, счётчики объектов и материалов, число обработанных команд.
**Когда:** первым делом в новой сессии — жив ли мост и та ли сцена открыта.

#### `get_scene_info`
Минимальный обзор сцены: имя, счётчики, первые 10 объектов.
**Когда:** быстрый peek, чем меньше вызовов — тем дешевле.

#### `get_object_info(name)`
Карточка объекта по имени: трансформы, видимость, материалы, меш-статистика
(верты/рёбра/полигоны), мировой AABB.
**Когда:** нужен один объект. Параметры: `name` (обязателен).

#### `get_hierarchy`
Дерево коллекций всей сцены с объектами, типами и флагами видимости.
**Когда:** понять структуру сцены целиком, найти нужную коллекцию.

#### `get_object_data(name)`
Полное read-only досье: трансформы, модификаторы (с настройками), констрейнты,
слоты материалов, кастом-пропы, экшен, mesh-статистика.
**Когда:** глубокий разбор объекта — перед правками или диагностикой.
Отличие от `get_object_info`: здесь вся начинка, там — только шапка.

#### `get_material_info(name)`
Досье материала: сводка нод, image-текстуры с путями, колорспейсами и
состоянием файла на диске (packed / missing).
**Когда:** проверить текстуры — особенно пропавшие файлы и колорспейсы.

#### `get_images_report`
Все изображения бленд-файла разом: пути, колорспейс, packed, **пропавшие**.
**Когда:** аудит текстур перед сдачей/экспортом. Аналог списка из
`File → External Data`.

### Рендер и скриншоты

#### `get_viewport_screenshot(filepath, max_size=800, format="png")`
Скриншот активного 3D-вьюпорта **как есть** (с оверлеями, гизмо, сеткой),
с даунскейлом до `max_size` по большей стороне.
**Когда:** агенту нужно «увидеть» твой вьюпорт — что ты видишь, то и он.
Путь — куда сохранить PNG.

#### `render_offscreen(filepath, mode="viewport", percent=100, width=None, height=None)`
Настоящий рендер **без окна рендера**:
- `mode="viewport"` — быстрый OpenGL-рендер текущего вида вьюпорта: та же
  камера и шейдинг, но **без оверлеев и гизмо**. Миллисекунды.
- `mode="camera"` — полный рендер движком сцены (Eevee/Cycles как настроено)
  из камеры сцены. Cycles на тяжёлой сцене может быть дольше таймаута 180 с.
- `percent` — процент разрешения (50 = половинное), `width`/`height` — явные.
- Формат файла определяется расширением: png/jpg/webp/bmp/tga/exr,
  без расширения добавится `.png`.
**Когда:** превью сцены/камеры, промежуточные кадры, проверка после правок.
Настройки рендера сцены (путь, формат, разрешение, media_type) временно
подменяются и **всегда восстанавливаются** — даже если рендер упал.

### Диагностика моста

#### `get_console_log(last_n=None, filter="", stream="")`
Кольцевой буфер (500 строк) Python-вывода консоли Blender: принты аддонов,
traceback'и, logging. Параметры: `last_n` — последние N строк, `filter` —
подстрока, `stream` — `"stdout"` / `"stderr"` / пусто (оба).
**Когда:** агент что-то сделал и молчит — что написалось в консоль?
⚠️ C-уровень (register-варнинги, отчёты операторов) Python не видит.

#### `clear_console_log`
Очистить кольцо. **Когда:** начать замер с чистого листа.

#### `list_instances`
Живые инстансы моста на машине: pid, порт, версия, сцена, свежесть хартбита.
**Когда:** открыто несколько Blender — какой порт к кому.

#### `get_bpy_api_info(query)`
Точные факты API из **живого** bpy — вместо угадывания сигнатур:
- `bpy.ops.export_scene.fbx` → карточка оператора: реальные имена/типы/дефолты
  всех параметров;
- `bpy.types.ImageFormatSettings` → обзор типа (свойства + функции);
- `bpy.types.ImageFormatSettings.file_format` → карточка свойства: тип, дефолт,
  **enum-итемы** (например, 16 живых значений вместо выдуманных);
- префикс `bpy.` можно опускать: `ImageFormatSettings.file_format`.
**Когда:** ПЕРЕД `execute_code` с незнакомым оператором или enum — проверять,
а не угадывать. Опечатка в имени типа вернёт ближайшие совпадения.

#### `get_pipeline_conventions`
Правила твоего пайплайна из `conventions.json` (лежит в папке аддона, можно
редактировать под себя): правило приёмника (контейнер t=0 r=0 s=1, габариты
запечены, переразмер >50 м — в отчёт, без авторескала), таблица
единиц/нейминга/UV по DCC (Blender/Maya/Houdini/Unreal), идемпотентность
нейминга, гайд по пресетам.
**Когда:** агент начинает ассет-работу — правила читаются из файла, а не
вспоминаются. Ответ из файла: без LLM, без сети.

### Пайплайн PROKLADKA

#### `list_presets`
4 экспортных пресета с уже разрешёнными настройками и note про приёмника:
`maya` / `houdini` / `ue` / `neutral`. Философия: отдающий экспортирует
нейтрально (метры, Y-up, binary FBX, модификаторы запечены), принимающий
конвертирует.

#### `export_fbx(path, preset="maya", scope="selected", collection_name="", overrides=None)`
Экспорт FBX по пресету:
- `scope`: `selected` (выделение + **все дети**, включая детей Empty),
  `collection` (вся коллекция, имя в `collection_name`), `scene` (всё).
- `overrides` — словарь свойств `export_scene.fbx` поверх пресета; каждое
  отклонение от контракта **эхом возвращается в отчёте** (аудируемость).
  Чужие ключи отвергаются с ошибкой.
**Когда:** отправить ассет в соседний DCC. Отчёт: файл, размер, объекты,
настройки, эхо оверрайдов.

#### `import_fbx(path, container=True, global_scale=None)`
Импорт по правилу приёмника: всё приезжает в контейнер EMPTY **t=0 r=0 s=1**,
правильные габариты запечены в геометрии, мировые трансформы сохранены.
Переразмерные меши (>50 м) попадают в поле `oversized` отчёта — **никогда не
рескейлятся автоматически** (никаких магических множителей).

### Исполнение

#### `execute_code(code)`
Произвольный bpy-код, stdout возвращается. Лаз на всё, чего нет в тулах выше.
**Когда:** точечная операция, которой нет в типизированных тулах.
⚠️ Перед незнакомым оператором/enum сначала `get_bpy_api_info`.
⚠️ Перед первой модифицирующей командой после паузы >10 с мост сам ставит
undo-чекпоинт — один Ctrl+Z откатывает всю сессию агента (см. ниже).

## 2. Панель (N-панель → MCP Socket)

### Главная панель
- **Статус-бейдж** — зелёный RUNNING / красный STOPPED, обновляется сам.
- **Last: …** — последняя команда и её статус (доказательство, что мост жив).
- **Start Bridge / Stop Bridge** — ручное управление TCP-сервером :9876
  (при включении аддона стартует сам).
- **Test Connection** — локальный самотест хендлеров без сокета.
- **Undo Agent Work** — откатывает всё, что агент сделал за сессию: перед
  первой модифицирующей командой после паузы >10 с мост сам ставит
  undo-чекпоинт. Отключается в префах (гигантские сцены).
- **Port: N** — фактический порт (может быть смещён при втором инстансе).

### Pipeline
- **Export FBX** — то же, что тул `export_fbx`, но руками: диалог файла +
  выбор пресета, путь попадает в клипборд.
- **Import FBX** — то же, что `import_fbx`: контейнер, переразмер в отчёт.

### Render
- **Render Offscreen** — то же, что `render_offscreen` руками: диалог файла,
  выбор режима Viewport/Camera, путь в клипборд.

### Agent Sessions
- **Replay Last Session** — перезапускает модифицирующие команды последней
  сессии агента по порядку: read-only пропускаются, каждый шаг отчитывается
  сам, отказ шага не стопит остальные. Шаги реплея пишутся в лог с
  `replay: true`. ⚠️ Реплей действует на **текущую** сцену — это черновик
  ритуала: для экспорта/анализа работает 1:1, модифицирующие шаги проверяй.
- **Copy Log Path** — путь JSONL последней сессии в клипборд. В файле каждая
  команда: время, тип, параметры, статус. Сессии лежат в
  `%TEMP%\mcp_socket\sessions\`, хранятся последние 30. Граница сессии —
  пауза 10 с (та же, что у undo-чекпоинта).

### Console Log
- Живой хвост кольца (8 строк) — прямо в панели.
- **Save to File** — весь буфер в `%TEMP%\mcp_socket\console_*.log`, путь в
  клипборд.
- **Clear** (крестик) — очистить кольцо.

## 3. Настройки (Preferences → Add-ons → MCP Socket)

| Настройка | Дефолт | Что делает |
|---|---|---|
| **Port** | 9876 | Порт TCP-моста (совпадает с blender-mcp) |
| **Auto port offset for second instance** | ON | Порт занят вторым Blender → взять следующий (9877…), реестр инстансов подскажет, кто где |
| **Undo checkpoint per agent session** | ON | Чекпоинт перед первой модифицирующей командой после паузы 10 с. Отключить на огромных сценах, если пуш чекпоинта тормозит |
| **Allow richer anonymous telemetry** | OFF | blender-mcp-совместимость телеметрии; лучше не трогать |

## 4. Подключение MCP-клиента

```json
"mcp-socket": {
  "command": "python",
  "args": ["<путь к репо>/mcp_server/server.py"]
}
```

Мульти-инстанс: вторая запись с `"args": ["…", "--port", "9877"]` или env
`MCP_SOCKET_PORT`. Кто где жив — `list_instances`.

## 5. Диагностика: куда смотреть

| Симптом | Действие |
|---|---|
| Агент молчит / команда висит | `get_console_log` — traceback? |
| «Unknown command» | Версии аддона и server.py разъехались — обнови оба |
| Порт занят при старте | Снять старый мост / перезапустить Blender |
| Реплей не находит шаги | В сессии были только read-only команды |
| Рендер вернул ошибку | Cycles долгий — уменьши percent или выбери viewport-режим |

## 6. Правила безопасности (напоминание)

- Мост слушает **только localhost**; `execute_code` исполняет произвольный
  Python без аутентификации — это норма для личной машины и недопустимо
  для общих/сетевых хостов.
- Таймаут клиента **не прерывает** выполнение кода в Blender: тяжёлый скрипт
  допишется после таймаута. Не бросай в мост скрипты без собственных гвардов.
